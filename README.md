# Heme/Onc Hub

**Live:** https://shankara-a.github.io/hemeonc/

Central landing page for the heme/onc toolkit. Static site (vanilla JS, no build step) on GitHub Pages.

- **Home** — links to the [PubMed Tracker](https://shankara-a.github.io/heme-onc-pubmed-tracker/), [K-Hub](https://shankara-a.github.io/heme-onc-hub/) and [Jobs](https://shankara-a.github.io/heme-onc-jobs/), plus recent updates.
- **Reviews** — one one-pager PDF per cancer type (rendered inline with PDF.js) with that disease's landmark trials beside it. Hover a trial for the takeaway card; click to pin it.
- **Trials** — the whole trial library, searchable and filterable. Deep links: `#trial/<id>`, `#trials/<disease>`, `#reviews/<disease>`.

## Layout

```
index.html            single page; tabs = Home / Reviews / Trials
assets/               styles.css · util.js (helpers, trial card, hover) · pdfviewer.js (PDF.js wrapper)
                      notes.js (spec -> HTML reading view) · reviews.js · trials.js · app.js
                      reviews.js · trials.js · app.js (routing + home)
data/diseases.json    disease registry: slug, name, short, group, onepager filename, aliases
data/trials.json      trial library (schema below)
data/onepagers.json   GENERATED by scripts/sync_onepagers.py — do not edit by hand
data/specs/<slug>.json GENERATED by scripts/export_specs.py — the one-pager spec, rendered as the Notes view
data/search.json      GENERATED by scripts/build_search.py — full-text index over one-pager content
pdfs/                 one-pager PDFs, copied from the Encyclopedia by the sync script
scripts/              sync_onepagers.py · export_specs.py · build_search.py · add_trial.py
                      pubmed_lookup.py · validate.py · publish.py
```

## Updating

### One-pagers (automatic)

The `cancer-one-pager` skill ends by running:

```bash
python3 scripts/sync_onepagers.py
```

which copies every PDF from `…/Fellowship/Encyclopedia/Encyclopedia/One Pagers/` into `pdfs/`, regenerates
`data/onepagers.json`, exports the spec files to `data/specs/` and rebuilds `data/search.json`, prints a
trial-coverage report (trial names in the PDF with no entry in `trials.json`), then commits and pushes.
Pages redeploys in about a minute.

Each one-pager therefore appears two ways: **Card** (the PDF, for print and bedside) and **Notes** (the same
spec reflowed as HTML, with a section TOC and deep links). A one-pager with no spec file — currently NSCLC —
shows Card only, and its search text comes from `pdftotext` instead.

A new PDF whose filename isn't in `diseases.json` gets a stub disease (group `unassigned`) — edit
`data/diseases.json` to give it the right name/group.

Flags: `--dry-run`, `--no-commit`, `--no-push`, `--src <folder>`, `--keep-orphans`.

### Trials

Use the `add-trial` skill ("add KEYNOTE-048 to head & neck"), or by hand:

```bash
python3 scripts/add_trial.py trial.json --push        # trial.json = one object or a list
python3 scripts/add_trial.py trial.json --update      # overwrite an existing id
python3 scripts/add_trial.py trial.json --new-disease '{"slug":"aml","name":"Acute myeloid leukemia","short":"AML","group":"malignant-heme"}'
```

Trial schema (required in bold):

| field | notes |
|---|---|
| **id** | kebab-case, e.g. `keynote-048` |
| **name** | display name, e.g. `KEYNOTE-048` |
| **disease** | slug from `diseases.json` |
| **year** | primary publication year |
| phase | `"3"` default; `"2"`, `"1/2"`, `"pooled"`… |
| **setting** | short: `1L metastatic`, `Adjuvant, stage III` |
| **descriptor** | one line: what was compared |
| **population** / **arms** / **primary_endpoint** / **results** | the card body |
| toxicity | optional |
| n | enrollment |
| **reference** | `Author A et al. Journal YYYY;vol:page` — PMID is resolved from this |
| pmid / nct | filled automatically when possible |
| highlights | list of strings — "why it matters" bullets |
| **takeaway** | one sentence shown in the hover card |
| tags | drugs, biomarkers, themes |
| source | `notion`, `onepager:<slug>`, `manual` |
| verified | bookkeeping only — every entry is checked against the primary abstract before it is added |

`python3 scripts/validate.py` checks everything; `python3 scripts/pubmed_lookup.py` fills missing PMIDs.

## Search visibility

`index.html` carries `<meta name="robots" content="noindex, nofollow, noarchive, nosnippet, noimageindex">`,
so the page is not indexed even though it is publicly reachable.

**A `robots.txt` in this repo would do nothing** — crawlers only read it at the domain root, which is
served by the `shankara-a.github.io` (al-folio) repo. The rules that block `/hemeonc/pdfs/` and
`/hemeonc/data/` live in **that** repo's `robots.txt`. The page itself is deliberately left crawlable
so the `noindex` above is actually seen and obeyed.

Note that `github.com/shankara-a/hemeonc` (the repo page) is itself indexed and describes this site;
none of the above affects that.
